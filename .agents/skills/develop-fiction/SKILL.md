# 小说开发

将作者的目标和取舍落实到可持续修改的故事资料与正文。先读取根 AGENTS.md、目标项目入口、进度和与本轮相关的设定；按需读取[小说 SOP](../../../_公共/教程/SOP/01_小说开发与分层修订.md)。

## 选择本轮工作

- 探索：提出有实质差异的方向，说明人物选择、读者体验和代价。未采用方案不回写为事实。
- 规划：把已采用方向细化为主线、章节和场景；不强制统一幕数或固定反转频率。
- 起草：读取当前场景所需上下文，再写完整可评估片段；避免在正文中混入计划和评语。
- 修订：遵守用户指定层级，先说明证据与影响，再在授权范围内修改；结构、场景、语言、校对按需要分层处理。

## 创作时的判断

1. 确认目标读者、题材承诺、人物欲望与阻力、关键选择和结局方向；缺失信息影响本轮时才澄清。
2. 使用[场景卡](../../../_公共/模板/场景卡.md)和[上下文包](../../../_公共/模板/创作上下文包.md)组织需要的事实；它们是辅助格式，不要求每次创建新文件。
3. 区分作者、视角人物、其他角色和读者已经知道的信息，检查事件时间与关系变化。
4. 沿用文体与叙事约定；缺少约定时从已确认正文提取候选特征，不能替作者悄悄改换作品声音。
5. 写完回查人物行动的因果、场景变化和前后承接。只将实际采用的变化更新到时间线、人物状态和伏笔。

## 交付

按当前任务交付方案、规划、正文或修订，更新相关索引与进度，说明保留的选择、修改影响和未解决项。用户只要求建议时直接回复，不强制落盘。

未立项时不自动复制项目模板。AI 模拟读者反馈标记为假设；需要质量评审时按[评审 SOP](../../../_公共/教程/SOP/05_作品评审与小样验证.md)提供有位置和影响的判断，不把自评分数当真实试读。
