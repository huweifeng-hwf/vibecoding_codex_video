# 作品评审与小样验证

状态：流程初版，待真实作品校准。参考 [AnimAgents](https://arxiv.org/abs/2511.17906)、[AnimeAgent](https://arxiv.org/abs/2602.20664)以及外部写作、短剧技能中的分层评审方法；下列标准为本仓库工作约定。

## 明确判断范围

记录受审版本、已读范围、实际观看／聆听范围、目标读者和创作者已选限制。未读、抽样、未播放和未知条件明确说明。作者自检、独立评审、AI 模拟与真实试读分别标记，不因切换提示词就声称独立。

## 评审维度

| 层级 | 核心问题 | 证据形式 |
| --- | --- | --- |
| 故事 | 目标、动机、因果、选择、代价与回收是否成立？ | 事件、章节、原文短引和对应关系 |
| 小说表达 | 视角、声音、具体性、节奏与情绪是否服务作品？ | 可定位段落与阅读影响 |
| 剧本／对白 | 是否可见可听、可表演，人物声音及潜台词是否有效？ | 场次、对白编号、朗读记录 |
| 镜头／表演 | 画面职责、构图、空间、动作、视线、口型和情绪是否成立？ | 实际时间点、镜头、画面或声音观察 |
| 制作与交接 | 资产、版本、素材、时间线和交付是否匹配？ | 文件、引用、参数和实际工具检查 |
| 读者／观众反馈 | 理解、期待、困惑、情绪与继续观看意愿如何？ | 实际试读／观看记录及样本条件 |

每条问题写清位置、事实、影响和希望达到的修订结果；“不够高级”“AI 味重”等判断需要落实到具体证据。审美偏好与破坏理解、连续性或既定目标的问题分开。

## 修订与复核

按阻断问题、重要改进和可选建议排序。先处理结构、人物与信息，再处理措辞或局部画面。用户同时要求修订时，按已有授权修复并复核受影响项；只要求评审时不覆盖源稿。

不设全作品通用的分数门槛。用立项目标定义可接受标准，保留遗留问题与取舍。

## 工具与镜头小样

使用[接入卡](../../模板/外部资源接入卡.md)记录：

1. 要验证的假设、代表性输入、来源与授权，以及已知限制。
2. 固定的剧本、参考资产、提示词和版本；对比时尽量一次改变一个因素。
3. 实际环境、模型／工具标识、参数、成功与失败次数、可用结果、耗时和总费用。
4. 角色与场景一致性、表演、动作完成、对白、口型、镜头衔接和编辑能力的观察。
5. 是否采用、适用范围、未通过原因与替代路线；不以供应商演示替代本剧小样。

计划与实际结果分开。未知费用不能填零，失败候选计入成本；仅在收到有效结果后计算每分钟合格成片成本。未得到当前任务的生成授权或预算时只交付计划。

## 工具事实与艺术判断

例如 `ffprobe -v error -show_format -show_streams -of json <文件>` 可以读取媒体信息；它不能确认角色表演或故事吸引力。[官方文档](https://ffmpeg.org/ffprobe.html)

技术检查的目标规格来自实际渠道或项目约定，不能用未核验的统一参数冒充平台要求。没有安装或运行工具时不报告技术检查通过。

## 交付

使用[评审记录](../../模板/作品评审记录.md)保存结论、版本、问题、修订顺序和复核证据。真实反馈用于调整方法；AI 自评用于定位候选问题，不能等同于读者验证或商业成功预测。
